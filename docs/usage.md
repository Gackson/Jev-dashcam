# Dashcam 使用与开发指南

[← 返回项目介绍](../README.md)

本文保留完整操作与工程细节；下方验证结果为此前开发记录，不代表每次文档更新都重新执行。

一个 SwiftUI macOS 原生 App：观察前台窗口变化，提取文字，并由 Jev 自动归入用户关注的话题。支持中文与英文 OCR，也保留网页开发模式。

## Mac App（推荐）

从 [v0.3.0 Release](https://github.com/Gackson/Jev-dashcam/releases/tag/v0.3.0) 下载 ZIP，解压后将 `Dashcam.app` 拖入「应用程序」即可启动。源码构建后可通过 `npm run install:mac` 安装到 `~/Applications/Dashcam.app`。App 内置运行环境，使用时不需要安装 Node.js、启动终端或打开 localhost。

- SwiftUI 原生窗口：话题内未选中资料时，以宽幅瀑布流展示截图卡片；选中卡片后才展开右侧详情，关闭或按 Esc 返回宽幅布局。详情模式左侧预览默认 300 点；拖动分隔线后会记住宽度，切换话题、关闭详情和重启 App 均可恢复。窗口缩小时临时限制宽度，不覆盖已保存偏好。切换话题自动收起详情，空话题标题始终位于顶部；卡片默认展示截图缩略图，详情默认展示来源截图，OCR 文字默认折叠，展开后可查看与复制。没有截图的资料显示文字入口。
- 每个话题标题右侧的 `copy prompt` 按钮可一键复制「资料库 Prompt」：在本机 `agent-context/<话题ID>.json` 写入该话题的完整快照，包含有效分类后的全部资料与截图引用，不受搜索筛选影响。粘贴给可访问本机文件的 agent 即可读取；远程 agent 需要另外提供 JSON 与关联截图。再次复制会更新快照。
- 同一窗口浏览时段的截图合为一个项目卡片，封面标注截图数量，展开后可用缩略图或上一张/下一张查看组内截图；详情内的话题调整和删除仅作用于当前截图；右键项目卡片可将整组加入或移出话题，或删除整组（包含被筛选隐藏的组内截图，删除前确认）。连续浏览规则：连续浏览同一窗口会续组，切走后 60 秒以内返回会续接原组，超过则另起一组；设置 → 采集与分组可调整为 0–3600 秒。依据系统窗口身份，标题变化不拆组，同一 App 的不同窗口不混组。每张截图依然独立归类、筛选和导出。此前没有窗口身份的历史资料会在备份数据库后，一次性按相同 App、相同标题且截图间隔不超过设置阈值补合并（近似推断，无法还原标题变化或未记录的窗口切换）；不修改截图、OCR、逐张归类结果。重启采集开始新的浏览时段。顶部“分组”独立控制项目卡片的展示，可选择不分组，或按来源 App、日期和小时（按本机时区、包含完整日期），组标题可折叠；筛选可组合来源 App 与今天、最近 7/30 天或自定义日期（含起止当天，按本机时区）。分组只改变展示，筛选和搜索不会缩小 `copy prompt` 的完整话题范围。
- 点击卡片缩略图或标题先打开资料详情；卡片图上的放大按钮和详情中的截图可打开大图预览，支持放大/缩小、双击、触控板捏合、双向滚动及 Esc 关闭。详情展开/收起即时切换；首次展开详情后左侧自动定位并高亮选中卡片；详情已展开时点击其他卡片保持列表位置，只有分组切换或预览栏宽度变化等布局调整才重新定位；再次点击已选中卡片的标题、缩略图或卡片空白处会取消选中，返回宽幅瀑布流。侧栏选中态使用主题浅绿色。
- 性能：瀑布流采用懒加载列，详情切换复用预览列表；截图在后台解码，缩略图、详情图和大图分别缓存。后台轮询只发布发生变化的数据，日期解析与格式化缓存复用。
- 白底叠帧 Dock 图标使用 Apple Icon Composer 原生分层格式，适配 Liquid Glass 深色、着色与透明外观；旧版 macOS 使用静态 ICNS。提供菜单栏入口、设置窗口、系统保存面板。
- 右键侧栏话题可编辑标题和简介。编辑不重跑现有资料及已排队任务，新采集资料使用更新后的话题信息；点击话题详情标题查看简介。
- 顶部按钮为 `Start Recording` / `Pause Recording`；点击侧栏底部采集状态也可开启或暂停。添加话题入口保留在侧栏。
- 归类失败页面及其右键菜单提供重试；卡片右键菜单可只重试该组失败资料。体验示例入口会打开已存在的示例，避免重复添加。
- `⌘N` 手动录入，`⇧⌘N` 创建话题，`⇧⌘E` 导出，`⇧⌘P` 开始/暂停采集，`⌘,` 设置，`⌘Q` 退出。
- 在「Dashcam → 设置 → 排除特定窗口」添加规则：可选择当前窗口，或手动填写来源 App 与标题。支持标题完全匹配和包含关键词（区分大小写）；选择窗口时按 App bundle ID 限定，手动填写时按 App 名称限定。同标题规则可能覆盖同一 App 下多个同名窗口；标题变化后只有关键词仍命中才会继续排除。规则即时生效并保存在本机 `window-exclusions.json`，可随时移除。命中时在截图和 OCR 前跳过，切换到其他窗口后自动继续，不影响已有资料。
- 主窗口关闭后 App 仍留在菜单栏；采集可继续。退出 App 会停止采集和内置服务，重开后默认暂停。
- 在「Dashcam → 设置」填写 TypeSafe API Key。密钥写入应用数据目录的 `settings.json`，权限为 `0600`，不会打入 App，也不会返回给资料界面。
- 开始采集时按系统提示，在「隐私与安全性 → 屏幕与系统音频录制」允许 **Dashcam**。授权后按 macOS 提示退出并重开 App。终端的旧权限不等于 App 的权限。

原生版默认数据目录：`~/Library/Application Support/Dashcam/`，包含 `jev.sqlite`、`screenshots/` 和配置。升级后会自动迁移旧默认目录 `Jev Note/`，沿用 bundle ID 保留偏好。设置 → 本地存储 → 更改存储位置，可选择或新建空文件夹；迁移前停止采集与服务，复制并校验资料库、截图、配置和备份，确认新服务可用后记住新位置。目标已有数据时拒绝覆盖，失败后恢复原位置。原目录保留为迁移时的备份，不会同步后续数据；迁移后录制保持暂停。外置磁盘断开时提示重新连接，不会创建空资料库。完整备份请复制整个目录；JSON 导出不包含截图文件内容。

### 构建与迁移

构建需要 Xcode 26 或更新版本（包含 Icon Composer / actool）、稳定代码签名证书，以及独立分发版 Node.js 22.13+（建议 24 LTS）。应用部署目标为 macOS 14+。

```bash
npm run build:mac
npm run install:mac
# 仅从网页原型迁移时执行；原生旧默认目录会自动迁移
# 首次迁移：先暂停网页采集、保持 Mac App 关闭，再执行一次
npm run migrate:mac
npm run start:mac
```

构建脚本优先使用 `JEV_NODE_BINARY` 指定的 Node，然后查找本机 Codex 的独立运行环境，最后检查 PATH 中的 Node。Homebrew Node 通常依赖外部 dylib，脚本会拒绝将这种不完整运行环境打包；可将 `JEV_NODE_BINARY` 设为 nodejs.org 官方 macOS 分发包中的 `bin/node`。

迁移会通过 SQLite 快照复制旧版 `data/` 的资料与关联截图，并迁移 `.env` 中的 TypeSafe 配置，保留旧数据。目标目录已存在时拒绝覆盖。迁移后两份资料库独立，网页和原生版不自动同步。可通过 `JEV_MIGRATE_SOURCE`、`JEV_MIGRATE_ENV`、`JEV_APP_DATA_DIR` 指定迁移路径；`JEV_APP_DATA_DIR` 也可用于启动隔离测试 App。

构建产物针对当前 Mac 架构，本机为 Apple Silicon。当前使用稳定的 Apple Development 证书签名，以保持更新间的录屏授权身份；尚未完成 Developer ID 签名与 Apple 公证，首次安装仍可能被系统阻止。构建脚本拒绝 ad-hoc 签名。

### 桌面架构

界面使用 SwiftUI / AppKit，不使用 WebView。App 包内包含独立 Node 运行环境，复用现有 SQLite、TypeSafe 分类与 Swift 采集器。内置服务只监听随机的 `127.0.0.1` 端口，每次启动生成独立令牌，对所有请求鉴权，不占用网页开发端口 4317。App 通过私有连接访问数据，用户不需要操作 localhost。

App 管理服务和采集器生命周期。父进程管道关闭时，服务会退出并清理采集进程；启动失败可在窗口内重试。采集器按 bundle ID 排除 Dashcam 的所有窗口，包括设置和弹窗。

## 网页开发模式

需要 macOS 14+、Xcode Command Line Tools、Node.js 22.13+。没有 npm 第三方依赖。

```bash
# 在项目目录中运行
npm run build:native
npm start
```

打开 http://localhost:4317 。现有 `.env` 会自动读取；不要将它提交到版本库。

```dotenv
TYPESAFE_API_KEY=your-api-key
TYPESAFE_MODEL=jev-latest
PORT=4317
```

1. 创建一个话题，并填写关注目标。
2. 点击「开始采集」，阅读采集说明，再开启。
3. 首次使用，在 macOS「系统设置 → 隐私与安全性 → 屏幕与系统音频录制」中允许启动服务的终端或 Codex。系统可能要求重启该应用；重启服务后再次点击开始。
4. 切换到浏览器或文档应用，停留或滚动阅读。回到 Dashcam 查看归类资料。
5. 点击「暂停采集」停止新的截图，已经入库的资料继续归类。

无需屏幕权限也能演示：点击「体验示例」加入 3 个话题与 4 份明确标注的合成示例，调用真实 Jev；或通过「手动录入」粘贴文字。示例包括相关和无关内容，不伪造模型结果。

## 原型范围

- Swift + ScreenCaptureKit：约 0.8 秒一次前台窗口采样。缩略图灰度差异判断变化，稳定一帧（约 0.8 秒）后 OCR，连续变化最多等约 3 秒，10 秒检查兜底。OCR 时长会影响实际采样间隔。
- Vision 在本地识别中文与英文，排除鼠标指针。截图仅在提取到新的足量文字时保存。按 bundle ID 跳过 Dashcam 自身，并跳过旧版 Jev-dashcam 标题的窗口、系统设置、Apple Passwords 和已列出的 1Password 应用 ID；此列表并不覆盖所有敏感网页。
- 第一版不监听点击、回车或键盘输入。前台窗口切换与画面差异共同触发检测。
- 待归类队列不再因达到 12 条而暂停采集。采集开启时，每 5 分钟批量检查并删除超过设置保留时长仍在等待首次归类的截图，每批最多 500 份。设置可调整为 1–720 小时，或一直保留；默认 1 小时，通常保留约 60–65 分钟，大量积压时可能更久。暂停或退出时不清理。正在归类、归类失败、已归类但未匹配话题、人工录入或已处理后再次归类的资料均保留。数据库使用批量事务，截图异步删除，不为每张截图设置计时器，也不在清理时执行 VACUUM。
- Node.js 内置 HTTP + SQLite，绑定 `127.0.0.1`。只允许本机 Host 与同源写入；模型密钥仅在服务端读取。
- 每个话题一个 Noul，同次请求独立判断，允许多标签与无匹配。自动归类阈值暂设 0.75，需根据实际样本调整。保留全部返回概率，允许人工调整。
- 相同文字（归一化后）不重复入库。每张新截图是独立资料，按该张截图的 OCR 正文独立判断所有话题；同 App、同标题、相似导航不再触发合并。模型提示明确忽略导航、侧栏和推荐内容，仍允许一张截图相关于多个话题，并支持逐张人工调整。
- 首次升级会自动将旧多截图资料拆成单张资料并重新归类。先在数据目录的 `backups/before-independent-capture-*` 保存 SQLite 和截图完整备份；旧组的文字、分数及人工标签另保存在数据库 `legacy_capture_groups` 表中。旧组标签不自动继承到每张截图，单张资料和手动录入保持原有结果。迁移以事务提交且只运行一次。截图按各自时间展示，资料数量因此会增加。
- 话题视图和新复制的 context 只包含独立归类后属于该话题的截图。升级前复制的快照需要再次点击 `copy prompt` 更新。
- 调用失败时保留资料，展示错误并支持重试；新话题会触发已有资料重新判断。串行队列降低模型调用压力。
- 数据保存在 `data/jev.sqlite` 和 `data/screenshots/`。支持全文子串搜索、删除资料、移除话题、导出 JSON。导出含截图文件名，完整备份请复制整个 `data/` 目录。

## 当前限制

只支持 Mac 当前前台应用的一个可见文档窗口；不采集所有显示器或后台标签页。截图权限需由用户在系统设置授权。系统锁屏、无可捕获窗口等状态会跳过或显示错误。浏览器链接不会自动读取，可在手动录入时填写。OCR 可能误识别或漏字，原始截图可供核对。归类每份资料最多使用前 24,000 字，完整原文仍留在本地。Jev 中文效果需用实际材料评估。这个版本尚未实现问答、长文总结、浏览器扩展与语义搜索。

## 验证

话题快照验证：`npm run test:mac`，覆盖话题范围、人工移除、搜索独立性、截图路径、私有文件权限、空话题及快照更新，同时验证来源/日期交集、本地日期边界、自定义起止日期和分组不合并资料；性能回归覆盖相同快照不触发发布、状态变化不重发资料、截图后台解码与分级缓存。

原生版验证：`npm run build:mac` 编译与签名校验通过；`npm test` 共 27 项测试通过（含窗口浏览时段边界、队列持续采集、定期清理及暂停保护、设置与分组持久化、窗口排除匹配），覆盖逐张归类隔离、旧组备份拆分及重复启动不重跑、桌面鉴权、随机端口、配置持久化、父进程退出清理、活动 WAL 资料库迁移和拒绝覆盖。实际 App 已验证加载迁移资料、话题筛选、搜索、原文展示与设置状态。`npm run test:storage:mac` 额外覆盖原生存储迁移、重启路径持久化、非空目录拒绝和磁盘断开恢复。屏幕录制仍需用户在系统设置中为 App 授权。

```bash
npm test
node --check server.mjs
node --check public/app.js
# 只检查屏幕权限，不申请权限、不截图
./build/jev-capture --check
# 在已有屏幕权限下，仅截取程序自己创建的合成窗口，验证截图与 OCR
./build/jev-capture --self-test
```

测试覆盖文字去重、段落合并、多话题判断、人工纠正、无匹配、API 请求形状和异常响应。

此前网页原型验证结果：8 项自动测试通过；合成窗口的 ScreenCaptureKit 截图与中英文 Vision OCR 通过；4 份示例调用真实 Jev 后，3 份匹配相关话题，咖啡随笔无匹配。浏览器中已验证创建话题、重新归类、搜索、查看原文和人工纠正。自动采集默认暂停，需点击开始。
